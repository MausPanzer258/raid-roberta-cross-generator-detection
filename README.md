Can AI-Text Detectors Generalize to Unseen Generators?
RoBERTa-base experiments on a selected subset of the RAID benchmark  
Research poster project | University of Trier
This repository contains data-preparation scripts, executable Jupyter notebooks, and recorded results for an empirical study of cross-generator generalization in binary human-vs-AI text detection.
Research question: To what extent can a RoBERTa-based AI-text detector generalize to previously unseen text generators?
Key results
We compared an IID (seen-generator) condition with leave-one-generator-out (LOGO) evaluation. In LOGO, the target generator was excluded from training and validation, and a fresh RoBERTa classifier was fine-tuned using the other three generators and human texts. Each IID/LOGO pair was evaluated on the same matched test records.
Target AI generator	IID AI-class F1	LOGO AI-class F1	Matched test rows
ChatGPT	98.68%	98.90%	448
GPT-4	98.98%	99.49%	390
Llama-Chat	99.24%	99.74%	390
Mistral-Chat	98.81%	99.28%	414
The overall IID test set contained 1,610 records and yielded 99.15% AI-class F1 (99.13% accuracy). The generator-specific rows above use balanced matched human/AI subsets, not the whole IID test set. Some human records are reused across generator-specific tests, so the four rows are not independent samples.
Interpretation: Strong detection performance persisted for all four held-out generators in this selected, controlled RAID subset. The small LOGO-minus-IID differences should not be interpreted as a statistically established superiority of LOGO. LOGO also changes training-set size and class balance. These results do not establish universal performance on arbitrary LLM outputs, languages, prompts, or attacks.

Data source and preprocessing
Dataset: RAID, Dugan et al. (ACL 2024). The code downloads the publicly distributed `train_none.csv` file from `https://dataset.raid-bench.xyz/train_none.csv`, rather than using the RAID official held-out test split.
From the original RAID training partition without adversarial attacks, the sampling script selects human text and outputs of ChatGPT, GPT-4, Llama-Chat, and Mistral-Chat, over five domains: abstracts, news, Reddit, reviews, and Wikipedia. For AI rows it selects `decoding=sampling` and `repetition_penalty=no`.
Preferred sampling is 4,000 human records and 1,000 records per generator (8,000 total), balanced by domain and binary class. The script has an adaptive quota if the source data cannot meet that target.
The splitting script removes 8 exact duplicate text rows in the original run, producing 7,992 unique text records. It uses `source_id`-aware grouped folds to reduce leakage of texts deriving from the same source.
Original fixed split sizes: 5,577 train / 805 validation / 1,610 test, with verified zero source-group and exact-text overlap across splits.
Only the selected subset of RAID's available domains, generators, and generation conditions was evaluated here. No adversarial text robustness is claimed.
Data redistribution: This repository does not include raw RAID documents or derived CSVs containing their full texts. Download the data from the original source using the scripts, subject to the source's applicable terms. The published manifest contains record IDs and metadata without raw text.
Reproducing the experiments
The original runs used Python 3.12.9, PyTorch 2.6.0+cu126, Transformers 4.51.3, and an NVIDIA GeForce RTX 4070 Laptop GPU. Code was executed using a Windows/Anaconda Jupyter environment. CUDA-enabled PyTorch should be installed according to the official PyTorch selector for your hardware and Python version; on a CPU-only machine, the notebooks' default GPU checks may stop execution.
The following commands are run from the repository root (the folder containing `scripts/` and `notebooks/`):
1. Create an environment
```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
# Install a suitable CUDA-enabled PyTorch build first, if using an NVIDIA GPU.
python -m pip install -r requirements.txt
```
If PowerShell blocks activation, open a suitable Anaconda Prompt or use the environment's `python.exe` explicitly. A Python 3.12 environment created in Anaconda is also suitable.
2. Download/select a balanced RAID subset
```powershell
python scripts/fetch_raid_balanced_final.py
```
This can download a large RAID CSV (about 0.8 GB) on first use. Alternatively, if you already have an official copy, use `--raw-csv PATH_TO_TRAIN_NONE_CSV`. The default output is `raid_balanced_final/raid_balanced.csv`, plus reports.
3. Deduplicate and create source-aware fixed splits
```powershell
python scripts/prepare_raid_splits_v2.py
```
Expected original-run outputs under `raid_experiment_data/`: `iid_train.csv`, `iid_validation.csv`, `iid_test.csv`, plus leakage and split reports. 4. Run IID first, then LOGO
```powershell

```
Open and Run All in this order:
`notebooks/RAID_RoBERTa_IID_Jupyter.ipynb`: trains a binary classifier on all four AI generators plus human text; selects its best checkpoint by validation AI-class F1; writes the IID results and the fixed per-generator test manifest under `iid_roberta_results_jupyter/`.
`notebooks/RAID_RoBERTa_LOGO_Jupyter.ipynb`: requires the same three split CSVs and the IID result files. It separately retrains RoBERTa from the base checkpoint for each held-out generator, with `TARGETS_TO_RUN = ALL_GENERATORS` by default, writing outputs under `logo_roberta_results_jupyter/`.
Both notebooks locate the repository root from the Jupyter working directory. Do not replace the LOGO test manifest or tune hyperparameters based on final test scores. The reported LOGO results use fresh fine-tuning from the original pretrained weights, not the already fine-tuned IID classifier.
Configuration and evaluation
Model: `FacebookAI/roberta-base`, binary labels human `0` / AI `1`.
Training: up to 3 epochs; max input length 256 tokens; batch size 4; gradient accumulation 4; learning rate `2e-5`; weight decay `0.01`; warm-up ratio `0.06`; seed 42.
Checkpoint: selected using validation AI-class F1. The held-out generator is absent from both training and validation for its LOGO fold.
Primary metric: AI-class F1; also report accuracy, precision, and recall.
Per-generator test: matched human and target-generator AI rows, same identities for IID vs LOGO.
The notebooks save model checkpoints locally; model weights are not distributed in this repository. Repeated fine-tuning may yield small differences due to stochastic computation and hardware/software versions. Published evaluation numbers are the original-run results, not a promise of bit-identical reruns.
Limits and research integrity
Very high scores apply to the selected RAID training subset and its specific preprocessing, not a cross-dataset or adversarial robustness assessment.
Text length, domain, formatting, language, and sampling artifacts may provide predictive cues. This experiment does not establish what representations RoBERTa learned or prove it identifies universal AI-text characteristics.
LOGO used fewer AI training records than IID, changing both training count and human/AI proportion; F1 changes cannot be attributed only to generator visibility.
Some human records are reused across separate target-generator test comparisons.
The original input text, trained model checkpoints, and sample-level full-text predictions are not distributed here. For the complete artifact mapping and provenance, read `results/README.md`.
